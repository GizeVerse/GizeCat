# Desktop Cat — Threat model

Scope: the Electron application (main process, two sandboxed renderers, koffi Win32 bindings), the v1.1 UI Automation helper process (`DesktopCatUia.exe`), its local files and its startup registry value, and the optional AI providers. Method: STRIDE over the data flows below, plus abuse cases specific to a screen-observing companion. v1.0 was checked by a 7-dimension adversarial review (63 findings, 53 confirmed and fixed) and v1.1 by a second review of the new code (57 findings, 48 confirmed and fixed), all with regression tests; see `docs/TEST_REPORT.md`.

## Assets

1. The user's screen contents and window metadata (titles, apps) — highest sensitivity.
2. Optional AI API keys.
3. Normal use of the PC (the overlay must never trap input or focus).
4. Local state files (settings, cat state, logs).

## Trust boundaries & data flows

```
 Win32 (user32/dwmapi/shell32) ──koffi──►  MAIN (trusted, Node)  ──HTTP(S)──►  AI provider (optional)
 desktopCapturer frames ──────────────►     │  ▲                                  (untrusted output)
                                             │  │ validated IPC (zod + sender check)
                         overlay renderer ◄──┘  └── settings renderer
                         (sandboxed, no Node, CSP, custom scheme)
 %APPDATA%\Desktop Cat\*.json  ◄── atomic writes / validated reads (untrusted input)
 HKCU\…\Run + StartupApproved\Run  ◄── our value only (koffi RegGetValueW read; Electron setLoginItemSettings write)
 DesktopCatUia.exe (child process, stdio JSON lines) ──UI Automation──► Edge/Chrome browser UI (geometry only)
       ▲ zod-validated, size-capped responses; spawned without a shell from the install folder
```

## Threats and mitigations

| # | Threat (STRIDE) | Mitigation |
|---|---|---|
| T1 | Renderer compromise → Node/OS access (E) | `sandbox:true`, `contextIsolation:true`, `nodeIntegration:false`; preloads expose only typed functions (never `ipcRenderer`); custom `desktop-cat://` scheme with path-traversal checks; strict CSP (`default-src 'none'`) as response header and meta; navigation, redirects, `window.open`, webviews, display-media and all permission requests denied; renderer network requests to non-app schemes cancelled. |
| T2 | Malicious/garbled IPC payloads (T, D) | Every inbound channel zod-validated, numeric ranges bounded, unknown keys rejected; sender frame/webContents must be one main created; two per-window overlay budgets (240/s for moves, hit regions and errors — the renderer itself caps moves at ~166/s — and 120/s for press/release/cancel/context/enter/leave), so press/release are never starved by moves. v1.1.1: the `settings:get-surface-diagnostics` reply is built from copied, clamped contract fields and validated against a strict schema in main before it is sent (counts, kinds, reasons, geometry; no titles, window ids or process names); `overlay:surface-lines` frames (geometry, kind and role only, ≤ 200 lines, ≤ 4 Hz, only while the session-only outline switch is on) are validated in the overlay preload. |
| T3 | Settings patch smuggling unsafe values (T) | `applySettingsPatch` rejects any leaf that does not survive strict parsing unchanged; unknown sections/keys rejected; `rejectConsentBypass` refuses patches that enable screen analysis or write the consent timestamp (only the consent actions can); global shortcuts must include Control, Alt or Super plus one non-reserved key — enforced in main, invalid stored values fall back to the default. |
| T4 | Prompt injection via on-screen text into the AI model (T, E) | Model output must be a strict JSON object matching `SceneReportSchema`; reactions from an 8-item allow-list mapped to existing cat behaviours; captions sanitised (control/bidi characters, URLs, e-mails, long numbers removed), never executed, never shown on the desktop; no tool/function execution path exists. Worst case: the cat reacts oddly. |
| T5 | Screenshot exfiltration (I) | Off by default; explicit consent timestamp required in code; cloud endpoints and cloud models require separate `allowCloud`; loopback detection resistant to `localhost.evil.com`, `*.localhost`, userinfo, IPv6/decimal tricks; models a loopback server forwards to the cloud (Ollama cloud models, aliases, `/v1`) are detected via the server and fail closed until confirmed local; Electron grabs whole displays at reduced resolution in memory; frames are cropped and masked before any resize/analysis/preview/AI encoding, display images released at once, buffers zeroed, never persisted; a 3-frame burst counts as one capture and only its first frame can reach AI; masks cover every shown window of excluded processes/titles including owned dialogs, tool windows and pop-ups; exclusions re-checked after each grab (frame dropped if a private window appeared or moved); nothing captured while a private window is in front, while locked, or if private windows cannot be located; privacy pause; tray always shows the mode. |
| T6 | Window titles leaking into logs/diagnostics (I) | Titles never leave the win32 module (not in `WindowInfo`); they are read only while screen analysis is on (title patterns are installed only then); logger redacts key-like strings; diagnostics export contains no titles. The UI Automation helper never requests the `Name` property (tab titles) and never queries web-content nodes; it returns rectangles, a selected flag and counts only. |
| T7 | API key disclosure (I) | Stored DPAPI-encrypted via `safeStorage`; refused if encryption unavailable; no `.bak` or quarantine copy of `secrets.json`, so a removed key is gone and can never be restored from a copy; never sent to renderers (only a boolean); never logged; sent only in the provider's auth header to the configured host; redirects refused; key changes abort in-flight requests and reset the circuit breaker. |
| T8 | Overlay blocks the desktop (D) | Overlays are click-through by default; main enables interaction only while the cursor is inside the cat's reported hit region and the renderer is healthy. The renderer re-reports its region at least every ~0.75 s while showing the cat; 3 s of silence or an `unresponsive` event → immediate click-through and any press/drag ends; the overlay is recreated (with backoff) if still silent 5 s later. Non-focusable windows never take focus; tray Quit, global hide shortcut, and "Interactions off" always work. The v1.1.1 surface-outline layer is `pointer-events: none` and not part of the reported hit region, so it can never make the overlay interactive. |
| T9 | Corrupt/hostile state files (T, D) | Field-level schema defaults; unreadable files quarantined (max 3 copies) and a file that exists but cannot be read is never overwritten; atomic writes with `.bak` (not for secrets); settings restored from `.bak` reset screen-analysis consent and `allowCloud`; bounded arrays and string lengths. |
| T10 | Resource exhaustion (D) | Bounded event queues (drop oldest), coalescing, capped logs (the cap holds even when rotation is blocked), capture/AI rate limits and circuit breaker, adaptive tick rates, no unbounded timers; taskbar sampling at 4 Hz idle (60 Hz only while a taskbar moves or the pointer is at a hidden auto-hide edge); the UIA helper starts lazily, has per-request timeouts, a restart budget and idle shutdown (v1.1.1: far candidate browsers are polled every 3 s and only while the cat is awake, so a sleeping, paused or hidden cat lets the helper exit), and is stopped on quit — measured in `docs/TEST_REPORT.md`. |
| T11 | Keylogging concern (I) | No keyboard hook; `GetAsyncKeyState` only for the left mouse button during drags; idle time only. Documented in PRIVACY.md. |
| T12 | Covert persistence (E) | v1.1: launch at sign-in is **on by default** and transparent — one `HKCU\…\Run` value with a fixed name (`io.github.enesiltas.desktopcat`), written by the *installed* app at its first normal start together with a one-time notice, visible and disableable in Task Manager → Startup apps and in Settings → General. A Task Manager disable is never overridden; an entry removed outside the app is respected; the app re-registers only after a reinstall (uninstaller marker), after an outside re-enable, or to repair its own stale path — and never while it was started from the Run key. Dev, test, portable/unpacked builds and `DESKTOP_CAT_LOGIN_ITEM=off` never write (write gate). The uninstaller removes the value. No services, scheduled tasks or elevation (`asInvoker`). Crash-guard relaunches are bounded (3 per 10 min) and disabled when the history cannot be persisted. |
| T13 | Tampering with the installed app (T) | Per-user install; Electron fuses verified on the packaged exe (RunAsNode, `NODE_OPTIONS` and inspect flags disabled; embedded ASAR integrity and only-load-from-ASAR enabled); test hooks, DevTools and `injectSurfaces` are never available in packaged builds. Two native binaries sit outside ASAR integrity — `koffi.node` and the UIA helper `resources\native\DesktopCatUia.exe`; like the app exe they live in the per-user install folder, so an attacker able to replace them already runs as the user. Builds are **unsigned** unless a signing identity is supplied → SmartScreen warning. |
| T14 | Supply chain (T) | Exact-pinned dependencies with lockfile; no dependency needs an install script, so installs use `npm ci --ignore-scripts` (npm 11 also warns about unapproved scripts; its `allowScripts` field is advisory) and the Electron binary is fetched explicitly; one runtime dependency shipped as a module (koffi; zod is bundled); `npm audit` over all dependencies (Electron and zod are devDependencies but ship) — 0 vulnerabilities on 2026-10-28; the CI workflow that would repeat this has not run yet. |
| T15 | Abuse of the UI Automation helper (T, I, D) | Spawned with a fixed path and no shell; accepts only decimal HWNDs of top-level `Chrome_WidgetWin_1` windows whose process image is `msedge.exe` or `chrome.exe`; Children-scoped queries along known class paths (never descendant searches into web content, which would also switch on the browser's web accessibility); never requests `Name`; responses zod-validated with line-size caps; per-request timeouts quarantine a hung window without disabling the feature; restart budget; private/excluded windows are never queried; the Settings switch stops it entirely. A browser-provider hang or crash affects only the helper, never the main process. |
| T16 | Overlay versus the Windows taskbar (D) | Full-monitor transparent topmost overlays are marked `NonRudeHWND` so Windows does not treat them as a fullscreen app and strip the taskbar's always-on-top flag (verified failure without it); the property is removed before an overlay is destroyed (also on outside close). The app does not fight the taskbar for z-order (it only restores its own topmost flag if lost). A click guard removes every visible taskbar rect and a 6 DIP band along each auto-hide edge from the cat's hit region, so the overlay never becomes interactive there and taskbar clicks and reveals reach Windows. |

## Out of scope / residual risk

- A local attacker running as the same Windows user can read DPAPI-protected secrets and modify the app; this is the Windows security boundary, not ours.
- The overlay is not shown above the secure desktop or exclusive-fullscreen games, and cannot receive input over windows of elevated apps (UIPI); this is a platform limitation.
- AI providers' handling of images is governed by their own policies; cloud use is opt-in.
- Unsigned builds cannot prove origin; distribute checksums and sign releases when an identity is available.
