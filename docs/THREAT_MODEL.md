# Desktop Cat — Threat model

Scope: the Electron application (main process, two sandboxed renderers, koffi Win32 bindings), the v1.1 UI Automation helper process (`DesktopCatUia.exe`), its local files and its startup registry value, and the optional AI providers. Method: STRIDE over the data flows below, plus abuse cases specific to a screen-observing companion. v1.0 was checked by a 7-dimension adversarial review (63 findings, 53 confirmed and fixed) and v1.1 by a second review of the new code (57 findings, 48 confirmed and fixed), all with regression tests; see `docs/TEST_REPORT.md`.

**1.4.0 release candidate (not released; nothing in it has run on a device).** 1.4.0 adds three surfaces, covered by T17–T20: the installable web app (a service worker, static hosting with a meta-tag CSP), the Android app (a hardened WebView with one native file bridge) and the portable profile file, which every host must treat as untrusted input. The macOS build is the same Electron app: it asks for no permission, keeps perception fail-closed, and its SMAppService login item is opt-in, off by default and never written at startup (the T12 principles). The Windows ARM64 build has the same surface as x64. The mitigations below for these surfaces are IMPLEMENTED in code; their tests are written and were not run for 1.4.0.

## Assets

1. The user's screen contents and window metadata (titles, apps) — highest sensitivity.
2. Optional AI API keys.
3. Normal use of the PC (the overlay must never trap input or focus).
4. Local state files (settings, cat state, logs).

## Trust boundaries & data flows

```
 Win32 (user32/dwmapi/shell32) ──koffi──►  MAIN (trusted, Node)  ──HTTP(S)──►  AI provider (optional)
 desktopCapturer frames ──────────────►     │  ▲                                  (untrusted output)
                                             │  │ validated IPC (zod + sender check)
                         overlay renderer ◄──┘  └── settings renderer
                         (sandboxed, no Node, CSP, custom scheme)
 %APPDATA%\Desktop Cat\*.json  ◄── atomic writes / validated reads (untrusted input)
 HKCU\…\Run + StartupApproved\Run  ◄── our value only (koffi RegGetValueW read; Electron setLoginItemSettings write)
 DesktopCatUia.exe (child process, stdio JSON lines) ──UI Automation──► Edge/Chrome browser UI (geometry only)
       ▲ zod-validated, size-capped responses; spawned without a shell from the install folder
```

## Threats and mitigations

| # | Threat (STRIDE) | Mitigation |
|---|---|---|
| T1 | Renderer compromise → Node/OS access (E) | `sandbox:true`, `contextIsolation:true`, `nodeIntegration:false`; preloads expose only typed functions (never `ipcRenderer`); custom `desktop-cat://` scheme with path-traversal checks; strict CSP (`default-src 'none'`) as response header and meta; navigation, redirects, `window.open`, webviews, display-media and all permission requests denied; renderer network requests to non-app schemes cancelled. |
| T2 | Malicious/garbled IPC payloads (T, D) | Every inbound channel zod-validated, numeric ranges bounded, unknown keys rejected; sender frame/webContents must be one main created; two per-window overlay budgets (240/s for moves, hit regions and errors — the renderer itself caps moves at ~166/s — and 120/s for press/release/cancel/context/enter/leave), so press/release are never starved by moves. v1.1.1: the `settings:get-surface-diagnostics` reply is built from copied, clamped contract fields and validated against a strict schema in main before it is sent (counts, kinds, reasons, geometry; no titles, window ids or process names); `overlay:surface-lines` frames (geometry, kind and role only, ≤ 200 lines, ≤ 4 Hz, only while the session-only outline switch is on) are validated in the overlay preload. v1.2: the `settings:get-behavior-profile` reply is validated against a strict, bounded schema before it is sent; a preset is one multi-section patch, applied atomically and rejected whole on one bad value, and a preset name that does not match the values sent is refused. |
| T3 | Settings patch smuggling unsafe values (T) | `applySettingsPatch` rejects any leaf that does not survive strict parsing unchanged; unknown sections/keys rejected; `rejectConsentBypass` refuses patches that enable screen analysis or write the consent timestamp (only the consent actions can); global shortcuts must include Control, Alt or Super plus one non-reserved key — enforced in main, invalid stored values fall back to the default. v1.2: the new opt-out list and its sidecar file hold only known behaviour ids (filtered, deduplicated, at most 64), so a damaged or downgraded file can never re-enable what the user switched off or smuggle other data; presets never touch consent, privacy, the login item, opt-outs, sound or appearance. |
| T4 | Prompt injection via on-screen text into the AI model (T, E) | Model output must be a strict JSON object matching `SceneReportSchema`; reactions from an 8-item allow-list mapped to existing cat behaviours; captions sanitised (control/bidi characters, URLs, e-mails, long numbers removed), never executed, never shown on the desktop; no tool/function execution path exists. Worst case: the cat reacts oddly. |
| T5 | Screenshot exfiltration (I) | Off by default; explicit consent timestamp required in code; cloud endpoints and cloud models require separate `allowCloud`; loopback detection resistant to `localhost.evil.com`, `*.localhost`, userinfo, IPv6/decimal tricks; models a loopback server forwards to the cloud (Ollama cloud models, aliases, `/v1`) are detected via the server and fail closed until confirmed local; Electron grabs whole displays at reduced resolution in memory; frames are cropped and masked before any resize/analysis/preview/AI encoding, display images released at once, buffers zeroed, never persisted; a 3-frame burst counts as one capture and only its first frame can reach AI; masks cover every shown window of excluded processes/titles including owned dialogs, tool windows and pop-ups; exclusions re-checked after each grab (frame dropped if a private window appeared or moved); nothing captured while a private window is in front, while locked, or if private windows cannot be located; privacy pause; tray always shows the mode. |
| T6 | Window titles leaking into logs/diagnostics (I) | Titles never leave the win32 module (not in `WindowInfo`); they are read only while screen analysis is on (title patterns are installed only then); logger redacts key-like strings; diagnostics export contains no titles. The UI Automation helper never requests the `Name` property (tab titles) and never queries web-content nodes; it returns rectangles, a selected flag and counts only. |
| T7 | API key disclosure (I) | Stored DPAPI-encrypted via `safeStorage`; refused if encryption unavailable; no `.bak` or quarantine copy of `secrets.json`, so a removed key is gone and can never be restored from a copy; never sent to renderers (only a boolean); never logged; sent only in the provider's auth header to the configured host; redirects refused; key changes abort in-flight requests and reset the circuit breaker. |
| T8 | Overlay blocks the desktop (D) | Overlays are click-through by default; main enables interaction only while the cursor is inside the cat's reported hit region and the renderer is healthy. The renderer re-reports its region at least every ~0.75 s while showing the cat; 3 s of silence or an `unresponsive` event → immediate click-through and any press/drag ends; the overlay is recreated (with backoff) if still silent 5 s later. Non-focusable windows never take focus; tray Quit, global hide shortcut, and "Interactions off" always work. The v1.1.1 surface-outline layer is `pointer-events: none` and not part of the reported hit region, so it can never make the overlay interactive. v1.2: while the cat clings to a screen edge or bails out of a covered surface, a fail-closed guard keeps the overlay click-through over any app window (obstacle rects stay in main; no obstacle data means click-through everywhere), a 300 ms hover dwell applies before a clinging cat becomes clickable, screen-edge climbs need the host's edge bands (absent means no climbs), and pounces and paw strikes keep a clearance from the pointer's hotspot measured from the hit region, so the next click still lands where the user aimed. 1.3.0 (interaction reliability, docs/gizeverse/13-interaction-reliability.md): without a press, renderer silence of 1.5 s (the hit-region age limit) counts as hung (3 s during a press); the Win32 button state ends a press only when the renderer has also gone quiet (400 ms, or 1.5 s after a held move), and once Win32 has read "up" for 400 ms with a quiet renderer the overlay takes the mouse only over the cat, never the whole display; a momentarily stale obstacle list keeps the last fresh cut-outs for at most 250 ms before failing closed; a bail-out guard is capped by the time grounded on the lost support (10 s ceiling); a recreate budget that is used up retries later instead of leaving the overlay unhealthy. |
| T9 | Corrupt/hostile state files (T, D) | Field-level schema defaults; unreadable files quarantined (max 3 copies) and a file that exists but cannot be read is never overwritten; atomic writes with `.bak` (not for secrets); settings restored from `.bak` reset screen-analysis consent and `allowCloud`; bounded arrays and string lengths. |
| T10 | Resource exhaustion (D) | Bounded event queues (drop oldest), coalescing, capped logs (the cap holds even when rotation is blocked), capture/AI rate limits and circuit breaker, adaptive tick rates, no unbounded timers; taskbar sampling at 4 Hz idle (60 Hz only while a taskbar moves or the pointer is at a hidden auto-hide edge); the UIA helper starts lazily, has per-request timeouts, a restart budget and idle shutdown (v1.1.1: far candidate browsers are polled every 3 s and only while the cat is awake, so a sleeping, paused or hidden cat lets the helper exit), and is stopped on quit — measured in `docs/TEST_REPORT.md`. Optional sound (v1.2) is rate-limited, played by one overlay only, and its audio context is closed when sound is off. |
| T11 | Keylogging concern (I) | No keyboard hook; `GetAsyncKeyState` only for the left, right and middle mouse buttons (drags, the typing detector's click exclusion and a content-free press count that ends hunts; v1.2), never for a keyboard key; idle time only. Documented in PRIVACY.md. |
| T12 | Covert persistence (E) | v1.1: launch at sign-in is **on by default** and transparent — one `HKCU\…\Run` value with a fixed name (`io.github.enesiltas.desktopcat`), written by the *installed* app at its first normal start together with a one-time notice, visible and disableable in Task Manager → Startup apps and in Settings → General. A Task Manager disable is never overridden; an entry removed outside the app is respected; the app re-registers only after a reinstall (uninstaller marker), after an outside re-enable, or to repair its own stale path — and never while it was started from the Run key. Dev, test, portable/unpacked builds and `DESKTOP_CAT_LOGIN_ITEM=off` never write (write gate). The uninstaller removes the value. No services, scheduled tasks or elevation (`asInvoker`). Crash-guard relaunches are bounded (3 per 10 min) and disabled when the history cannot be persisted. |
| T13 | Tampering with the installed app (T) | Per-user install; Electron fuses verified on the packaged exe (RunAsNode, `NODE_OPTIONS` and inspect flags disabled; embedded ASAR integrity and only-load-from-ASAR enabled); test hooks, DevTools and `injectSurfaces` are never available in packaged builds. Two native binaries sit outside ASAR integrity — `koffi.node` and the UIA helper `resources\native\DesktopCatUia.exe`; like the app exe they live in the per-user install folder, so an attacker able to replace them already runs as the user. Builds are **unsigned** unless a signing identity is supplied → SmartScreen warning. |
| T14 | Supply chain (T) | Exact-pinned dependencies with lockfile; no dependency needs an install script, so installs use `npm ci --ignore-scripts` (npm 11 also warns about unapproved scripts; its `allowScripts` field is advisory) and the Electron binary is fetched explicitly; one runtime dependency shipped as a module (koffi; zod is bundled); `npm audit` over all dependencies (Electron and zod are devDependencies but ship) — 0 vulnerabilities on 2026-10-28; the CI workflow that would repeat this has not run yet. |
| T15 | Abuse of the UI Automation helper (T, I, D) | Spawned with a fixed path and no shell; accepts only decimal HWNDs of allow-listed top-level windows, checked with Win32 data only (class, full image path, a required child class) before any UI Automation call (`UIA_NEVER_QUERY`: Notepad, VS Code and other Electron apps, and Firefox are refused outright; v1.2 adds the WinUI TabView reader for Windows Terminal, and for File Explorer behind a request-rate limit, a kill switch and a REAL soak gate, off until that soak passes); Children-scoped queries along known class paths (never descendant searches into web content, which would also switch on the browser's web accessibility); never requests `Name`, `AutomationId`, `LegacyIAccessible*`, the Value or Text patterns, `HelpText`, `FullDescription` or `ItemStatus`; responses zod-validated with line-size caps; per-request timeouts quarantine a hung window without disabling the feature; restart budget; private/excluded windows are never queried; the Settings switch stops it entirely. A browser-provider hang or crash affects only the helper, never the main process. |
| T16 | Overlay versus the Windows taskbar (D) | Full-monitor transparent topmost overlays are marked `NonRudeHWND` so Windows does not treat them as a fullscreen app and strip the taskbar's always-on-top flag (verified failure without it); the property is removed before an overlay is destroyed (also on outside close). The app does not fight the taskbar for z-order (it only restores its own topmost flag if lost). A click guard removes every visible taskbar rect and a 6 DIP band along each auto-hide edge from the cat's hit region, so the overlay never becomes interactive there and taskbar clicks and reveals reach Windows. |
| T17 | Profile import as untrusted input (T, D, E) (1.4.0) | A profile file comes from anywhere, so `src/shared/profileTransfer.ts` treats it as hostile: a 64 KiB UTF-8 byte cap before parsing; a BOM stripped; `JSON.parse` inside try/catch; the `kind`, `format.major` and `character` checked first, and a newer major refused, never parsed best-effort; only allow-listed keys read (zod objects with explicit keys, never `z.record`, so `__proto__` and unknown keys are dropped); every settings leaf must survive `applySettingsPatch(defaultSettings(), leaf)` unchanged, and only primitives and flat id lists reach that check, so deep nesting cannot overflow the stack; failed leaves are skipped and listed by allow-listed path, never echoing file content; the cat section is all-or-nothing (name cleaned of invisible and bidi characters and limited to 1–24 code units, `catId` matching `^[A-Za-z0-9-]{8,64}$`, `bornAt` finite, non-negative and capped at now, all 7 traits in 0..1). The file never carries the perception, AI, login-item or diagnostics sections, so an import cannot reach consent (`rejectConsentBypass` still runs as defence in depth); a privacy floor (`IMPORT_NEVER_ENABLES`) keeps tab-strip reading off when the device has it off. A preview comes before apply, and apply runs in memory with nothing half-applied. Desktop wiring (`src/main/profile/`): a file is read only from a path that main's own open dialog returned, and the renderer never sends a path or file content; the size is checked before reading and the read stops past the cap; the parsed profile waits in one pending slot behind a 128-bit token bound to the settings window that asked, for 10 minutes; apply limits the patch to `general.catName` and the appearance, behaviour, interaction and sound sections, re-checks it with the renderer-patch guards (`rejectConsentBypass`, `rejectMainOwnedPatch`, `rejectMainOwnedFields`), commits the settings, then adopts the cat, and puts the settings back if the adopt fails; an export replaces only a file the save dialog confirmed: when main adds the `.json` extension that path is only created (flag `wx`), and if it already exists the exact path the user chose is written instead; logs carry codes and counts only, never the name, a path or file content. Web and Android: the size of a picked file is checked before it is read, the page parses it with the same module, and nothing changes until the user confirms the preview. |
| T18 | Service worker scope and cache (T, I, D) (1.4.0) | The web app's worker (`src/web/sw.ts`) is registered with scope `./` and `updateViaCache: 'none'`, only on secure http(s) pages, never in the Android app, on `file://` or in a development build. It handles only same-origin GET requests inside its scope: navigations to the app's own page (the scope root and `index.html`) get the cached `index.html` (stored as a plain, non-redirected copy), shell files come cache-first, everything else passes through untouched, including navigations to other pages on a shared origin. The precache list is fixed at build time and the build fails unless it equals the files on disk. The cache name carries a hash of the registration scope, the version and a content hash; activation deletes only older caches of the same scope (never another copy's or another site's caches on a shared origin), and there is no runtime caching (no response chosen at run time is ever stored) and no message handler. Where headers can be set, `sw.js` runs under `default-src 'none'; connect-src 'self'`. Residual: whoever controls the host can serve a hostile `sw.js`, which is the same power as serving a hostile page; a worker persists on the device until the site's data is cleared; no kill switch ships (a self-unregistering `sw.js` that deletes `gizecat-shell-*` is the remedy). |
| T19 | Static hosting: a meta-tag CSP and the shared `github.io` origin (T, I) (1.4.0) | GitHub Pages and many static hosts cannot send headers, so the policy is the CSP meta tag only (`default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self'; manifest-src 'self'; worker-src 'self'; connect-src 'none'; base-uri 'none'; form-action 'none'; object-src 'none'`), placed before any script and pinned by the build. A meta CSP cannot set `frame-ancestors`, so the page can be framed there; it has no account, no network and nothing worth clickjacking, and Start over needs a second, in-sheet confirmation. `README-web.txt` lists the optional headers (`frame-ancestors 'none'`, `nosniff`, `no-referrer`) for hosts that allow them. On a GitHub project site, localStorage and Cache Storage are shared with every other Pages site of the same owner, and a root-scoped worker from the owner's user site could control GizeCat's path. GizeCat stores no secrets there (only the cat and its settings), every read goes through the zod schemas and migrations (a damaged value gives a fresh cat), and cleanup touches only its own caches. A custom domain, or an account used only for this site, removes the sharing; that is an owner decision. Public hosting does not exist yet (REQUIRES_OWNER_CREDENTIALS). |
| T20 | Android WebView and its file bridge (E, T, I) (1.4.0) | No third-party content can run in the WebView: the asset loader serves only the app's own files from `https://appassets.androidplatform.net/assets/`, every other request gets an empty 404, navigation outside that origin is blocked and no other app is launched; the page's CSP applies; there is no internet permission. There is no `addJavascriptInterface`. The only bridge, `gizecatNative`, is added with `addWebMessageListener` for the exact origin above (and only where the WebView supports it); messages are accepted only from the main frame, with the origin re-checked, as strings with a capped raw size, with exactly the keys `type`, `name`, `mime`, `text`, type `saveFile`, `mime` `application/json` or `text/plain`, and `text` at most 256 KB in UTF-8. The name is sanitised (path parts, control and Unicode format characters, reserved characters and leading dots removed; at most 100 characters; extension forced to match `mime`). One save at a time; the user picks the destination in the system "save as" screen, so the app can write nowhere by itself; the reply carries only `ok` and a reason code. Opening a file uses the system picker (JSON or plain text, one file), and its contents are then untrusted input (T17). The WebView denies every web permission request and geolocation prompt; file and content URL access, multiple windows and zoom are off; mixed content is never allowed; there is no download listener; DevTools exist only in debuggable builds; a crashed renderer is replaced, with a static message after 3 crashes in 60 s (a renderer killed by the system for memory is not counted and is recreated when the app comes back; reopening the app clears the message). Back runs one fixed script in the page (`evaluateJavascript`, no data passed) that closes the topmost open dialog; only when none is open does the app go to the background. Residual: an outdated WebView without `WEB_MESSAGE_LISTENER` has no save bridge (fails closed); the trial APK is debug-signed and must never be distributed as a release. |

## Out of scope / residual risk

- A local attacker running as the same Windows user can read DPAPI-protected secrets and modify the app; this is the Windows security boundary, not ours.
- The overlay is not shown above the secure desktop or exclusive-fullscreen games, and cannot receive input over windows of elevated apps (UIPI); this is a platform limitation.
- AI providers' handling of images is governed by their own policies; cloud use is opt-in.
- Unsigned builds cannot prove origin; distribute checksums and sign releases when an identity is available.
- 1.4.0: the Windows ARM64 installer, the macOS ad-hoc zips and the Android release APK and AAB are unsigned or ad-hoc signed, and the Android trial APK is signed with a development key. Only checksums tie them to the release. Developer ID signing, notarization and an Android release key need the owner's credentials.
