# v1.1.1 diagnosis: the cat never leaves the floor

Date: 2026-10-29. Machine: Windows 11 Home 10.0.26200, one 1920×1200 display at 125 % (1536×960 DIP), auto-hide bottom taskbar (work area = full screen). Installed build: v1.1.0, byte-identical to the repo's release build (`app.asar`, `DesktopCatUia.exe` SHA-256 match).

## Report

The installed cat walks the floor and reacts to the mouse but never climbs onto windows and never stands on browser tab strips.

## Evidence from the user's install (REAL, read-only)

- `settings.json`: nothing disabled (`disabledBehaviors: []`), autonomy 0.6, size 1, perception `local-stats` (consented).
- `cat-state.json` after ~23.5 min awake: `windowsInspected 0`, no favourite spots, support `floor`; boredom 0.02.
- `main.log`: window tracking and the taskbar are found; the tab-strip helper starts and stops ("tab strips idle") four times; **nothing logs surface counts or reachability**, so the failure was invisible.
- Window layout snapshot (geometry, class, exe only; no titles): the foreground window and two others are **maximized** (covering the whole screen with an auto-hide taskbar); the floating windows (Claude, Settings, Obsidian, Docker, a second Chrome) end **82–485 px above the floor** and their tops are **907–1095 px above it**.

## Root causes (each confirmed by code reading, a headless replay of the real geometry through the real provider/world/graph/sim, and the real dev app with own throwaway windows)

| # | Stage | Cause | Evidence |
|---|---|---|---|
| RC1 | Navigation graph (blocking) | From the floor the cat can only (a) jump onto a ledge ≤ 420 DIP (525 px) above its feet, or (b) step onto a window side whose foot is within 0.6 body heights (48 px) of its feet (`constants.ts` `maxJumpUpDip`, `wallReachBodyHeights`; `surfaceGraph.ts` `jumpEdge`/`mountEdge`). Real floating windows end 82–485 px above the floor and their tops are ~1000 px up, so the floor has **zero edges** to any window surface. There is no "leap and cling" onto a side. | Replay: 0 floor edges for every floating window of the user's layout; REAL app: a typical window `[308,140,1284,892]` was never reached (0/913 samples), while a user window whose side reached y≈1140–1162 was climbed by itself. |
| RC2 | Discovery (by design) | A maximized window in front covers every window below it and offers no surfaces itself (`windowSurfaces.ts` `offersSurfaces`, occlusion in `provider.ts`). With the captured z-order the registry holds **0 surfaces**. A maximized browser's strip sits at the screen's top edge with no room above it. | Replay A: 0 surfaces in 4×60 sim-min. |
| RC3 | Climb execution (blocking for browsers) | Climbing a browser's side makes it "of interest"; ~0.4 s later its tab strip replaces `windowTop:<hwnd>` in the listing, but the climb keeps the stale `topKey` (`mover.ts` `beginClimb`), finds no top at the corner and **climbs back down**. Climb cooldown (90–240 s) outlasts the strip's 60 s lifetime, so it repeats forever. | Replay B2: 0 of 25 browser mounts reached a top; with strips off 23/25. |
| RC4 | Tab-strip discovery | The helper measures a browser only when its top edge is within 300 DIP (375 px) of the cat (`provider.ts` interest radius). From the floor that needs a window top at y ≥ ~820, so normal browsers are never measured — the "tab strips idle; stopping the helper" log pattern. | REAL app, own Edge `[308,140,1284,892]`: idle 43/43 checks, no tabStrip ever; lowered to y=850: strip measured. |
| RC5 | Destination selection | `tabStripTarget` only accepts strips reachable **without climbing** (`canReach(point, 'noClimb')`); `perchTarget` only considers `windowTop` ledges and only the 3 nearest before checking reachability (`tabStripTarget` the 2 nearest). | Code; replay B2f: strip listed, 0 strip/perch targets in ~200 decisions. |
| RC6 | Graph (secondary) | A pull-up from a side onto a tab strip only works if the strip's anchor span starts within 1.25 body widths of the side; the strip excludes the browser's left controls, so from a right side it never works and from the left it depends on toolbar width. | Code arithmetic. |
| RC7 | Decision weights (suppressor) | With the user's profile (boredom ≈ 0.02, frequent typing), surface options score ~0.08 against ~0.25 for idle/wander, chosen by a top-4 softmax at T = 0.12; detected typing multiplies excursions by ~0.3×0.3; a failed trip still starts the 90–240 s cooldown; explore approach times out at 15 s although a ~950 px climb takes ~17 s. A default configuration can therefore suppress exploration indefinitely. | REAL app: a reachable top with the user's stats was never chosen in 1438 sim-s; with boredom 0.6 the cat jumped up at 133 sim-s. |

Ruled out (refuted with evidence): coordinate/DPI mismatch (one physical-px space end to end; per-monitor-v2 in main and the helper), fullscreen false positives (maximized windows are not classified fullscreen, the cat stays visible), missing/packaged helper (present, identical, starts), disabled settings or migration (fresh install, nothing disabled).

Not verifiable without reading titles (privacy): whether any user window was title-excluded while local-stats analysis was on. Diagnostics now count exclusions.

## Why the tests did not catch it

Every climbing/reaching test used geometry chosen to be reachable (walls ending exactly on the floor, tops 240–345 px up, strips listed from t=0 within jump reach); the test fixture `surfacesFromWindows` did not behave like the provider (no corner inset, no occlusion, no strip replacement); the behaviour harness skipped the app's 4 DIP floor inset; the only REAL-window E2E test asserted that a window is *listed*, not *reached*, and skipped when the probe was covered; nothing asserted liveness (a cat on the floor reaches a surface) or logged reachability.
