# GizeCat 1.4.0 (release candidate): one cat, more devices

> **Draft, not published.** GizeCat 1.3.0 stays the current release until the owner approves 1.4.0. The files and checksums below are those of the candidate build made on 2026-11-08 from commit `35a41a6` on the branch `release/1.4.0-universal-devices`. A later rebuild gives different checksums.

GizeCat is a small cat that lives on your screen and never gets in the way of your clicks. It is the first character of **GizeVerse**: free, open source and MIT-licensed.

1.4.0 brings the same cat to more devices: Windows on Arm PCs, Macs, iPads and Android tablets. **This is a candidate. Nothing in 1.4.0 has run on any device yet.** The files below were compiled or packaged on the project's Windows PC; a build is not a test. Please tell us what happens on your device (see "Feedback").

## What's new

**Windows**
- One installer per architecture. Pick `-x64` for almost every PC and `-arm64` for a Windows on Arm PC (Settings → System → About → System type). The ARM64 installer stops with a clear message on a PC that is not Windows on Arm.
- Same app identity as 1.3.0, so installing over 1.3.0 is an upgrade that keeps your cat (the 1.4.0 upgrade has not been run). The installer and shortcuts are still called "Desktop Cat".

**macOS (Intel and Apple Silicon)**, in the code, with no package yet
- The desktop cat on the floor of each screen (no window climbing on macOS), in a click-through panel that stays below menus and the Dock.
- A menu-bar icon (its click opens the menu), a Dock icon you can turn off, and an opt-in "Open at login".
- No permission prompts: no Accessibility, Screen Recording, camera or microphone. Screen analysis is not available on macOS.

**iPad**
- The installable web app: open it in Safari, then Share → **Add to Home Screen**. It works offline once installed. No App Store app; the cat lives inside its own window, because iPadOS lets no app draw over other apps.
- No public address exists yet. You can host `GizeCat-web-1.4.0.zip` on any HTTPS static host (see `README-web.txt` inside).

**Android tablets**
- A native app with **no permissions at all** (not even internet), no cloud backup and a hardened WebView, showing the same cat as the web app. Android 10 or later.
- The release APK and AAB are unsigned until the owner creates a release key. The trial APK is for sideload trials only.
- Or install the web app from Chrome (menu → Install app) once it is hosted.

**Every device**
- **Take your cat to another device:** save your cat to a file and load it elsewhere (Settings → Personality on Windows and macOS; the settings sheet on tablets). You see what a file would change before anything changes. Nothing is uploaded; it is a copy, not a sync. A file never contains API keys, screen-analysis or AI settings, window titles or folder paths.

## Known limitations

- **Nothing has run on a device**: not the Windows installers for 1.4.0, not the ARM64 build, not macOS, not the iPad or Android web app, not the Android app.
- **Unsigned** everywhere. SmartScreen warns on Windows, and Smart App Control may block the installers.
- **macOS has no package yet** and is floor-only in the code: no window climbing, no fullscreen detection, no screen analysis.
- **Tablets**: the cat lives inside its own window; Safari may clear a Safari tab's data after 7 days without a visit (install the web app to keep your cat); an outdated Android System WebView shows no cat.
- **Some settings texts on macOS still say "PC"** or mention Windows shortcuts.
- **Not tested** on Windows 10, multi-monitor or mixed-DPI hardware, or with real AI providers.

## What ran for this candidate

- Static checks: TypeScript (`tsconfig.node.json`, `tsconfig.web.json`) and ESLint over the whole repository, on the final code.
- Builds: the production web bundle and its package; the Windows x64 and ARM64 NSIS installers; the Android release APK, AAB and trial APK (Gradle).
- Static inspections of what was built, without running it: both Windows unpacked builds through `scripts/check-win-payload.mjs` (PE machine, only the right koffi binary unpacked, app.asar holding only the app, asar integrity, fuses: all passed), and the Android APKs through `apkanalyzer` (no permissions, the right application IDs, versionCode 10400, minSdk 29, targetSdk 36, not debuggable).
- An independent review of the 1.4.0 changes; its confirmed findings were fixed before this build. One was a packaging defect that made the first Windows build pack the whole project into the installers; that build was deleted and never distributed.
- **No test suite was executed for 1.4.0** (no unit, integration, end-to-end, install or upgrade test), and nothing was run on a device, an emulator or a virtual machine.

## Owner actions before publishing

1. **Decide whether to publish 1.4.0 at all.** Keep 1.3.0 as Latest until then; consider publishing 1.4.0 as a pre-release.
2. **Run the tests that were written and not run**, at least `node .claude/scripts/verify.mjs fast` and, on Windows, `verify full` and `npm run test:web`. Until they pass, no test claim may appear in these notes.
3. **Windows:**
   - Confirm the installer names `Desktop-Cat-Setup-1.4.0-x64.exe` / `-arm64.exe`.
   - Run the 1.3.0 → 1.4.0 x64 upgrade on a disposable machine (the `installer-check` workflow or a VM), never on a PC with a real install.
   - For any ARM64 claim beyond COMPILED_OR_PACKAGED: a Windows on Arm PC or disposable ARM64 VM (`install-test.ps1 -Arch arm64`, and `upgrade-test.ps1 -OldInstaller Desktop-Cat-Setup-1.3.0.exe -Arch arm64` for the cross-arch upgrade).
   - Optional: a code-signing certificate.
4. **macOS:**
   - Produce packages: `npm run package:mac:adhoc-docker` on a PC whose Docker works (ad-hoc test zips), or the notarized route: join the Apple Developer Program, create a Developer ID Application certificate and an App Store Connect API key, create the GitHub Environment `macos-signing` with yourself as required reviewer **before** the first dispatch, add its secrets, then dispatch `macos-packages.yml`.
   - Run the Mac checklist ([docs/gizeverse/04-macos.md](../gizeverse/04-macos.md)) on a real Apple Silicon and Intel Mac.
5. **Web app:** decide whether it may be public. If yes, enable GitHub Pages (Source: GitHub Actions) and dispatch `pages.yml`, or choose a custom domain (it also avoids the shared `github.io` origin). Then add the real address to the README and these notes. Never invent one.
6. **Android:**
   - Confirm the permanent identifiers: `io.github.gizeverse.gizecat`, the launcher name GizeCat, the origin `https://appassets.androidplatform.net`.
   - Create the upload keystore yourself and sign the APK and AAB; back up the key offline.
   - Decide whether to attach the debug-signed trial APK.
   - Register for Android developer verification if APKs will be distributed outside Play; set up Google Play (account, Play App Signing, data-safety form, a privacy policy address of your choice, content rating, store graphics) if wanted.
   - Decide the cloud-backup policy (default: off; device-to-device transfer on).
   - An in-app licences page is needed before a store release.
   - Run the app on a real tablet before any Android status moves.
7. **Confirm the profile choices:** the frozen tag `gizeverse-character-profile`, the file name pattern `gizecat-<name>-<YYYY-MM-DD>.json`, "what it has learned" off by default, sound settings travelling, tab-strip reading never re-enabled by an import.
8. **Issue template:** consider adding iPadOS, Android and Windows on Arm to the Platform report form's operating-system list (`.github/ISSUE_TEMPLATE/platform_report.yml`).
9. **README:** when 1.4.0 is published, update the "Current release" line under "Download and install".
