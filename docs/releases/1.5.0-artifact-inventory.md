# GizeCat 1.5.0 release candidate: artifact inventory and static verification

This is the evidence record for the 1.5.0 release-candidate build: what was built, from which commit, how it was inspected, and what was **not** verified. Nothing here is published, tagged or attached to a GitHub Release.

**Verification level, stated plainly.** Every artifact below is **COMPILED_OR_PACKAGED** and **statically verified** (type-check, lint, a read-only adversarial code review, and static inspection of the built files). **Nothing in 1.5.0 was run by anyone**: no automated test, no emulator or simulator, no application launch, no installer run, no device. The only runtime evidence in this project for the floating cat is the owner's real-phone check of **1.4.2** on one Android phone, which predates all of the Living Companion code.

## Static inspection results

**Android (aapt2 and apksigner, read-only).**

| Check | Trial APK | Release APK |
|---|---|---|
| Application id | `io.github.gizeverse.gizecat.trial` (frozen identity plus the `.trial` suffix) | `io.github.gizeverse.gizecat` |
| Version | `1.5.0-trial`, code 10500 | `1.5.0`, code 10500 |
| Permissions | exactly four: `SYSTEM_ALERT_WINDOW`, `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_SPECIAL_USE`, `POST_NOTIFICATIONS` | the same four |
| Native libraries (`lib/`) | none | none |
| Code | one `classes.dex` | one `classes.dex` |
| New permission since 1.4.2 | none | none |

The AAB contains `base/manifest/AndroidManifest.xml` and `BundleConfig.pb` and no `lib/` entries; its manifest is protobuf-encoded, so its permission list was not parsed separately (it is produced by the same manifest merge as the APK's).

**Windows (`scripts/check-win-payload.mjs`, which reads file headers and never runs a binary).** Both `win-unpacked` (x64) and `win-arm64-unpacked` passed with no failures and no warnings: the executable's PE machine type matches the architecture, the matching `koffi` native module is present and unpacked, the asar integrity resource and the fuse wire match `electron-builder.yml`, and the asar holds only the application (no sources, docs or old installers).

**Source (type-check and lint on the committed tree).** `tsc -p tsconfig.node.json`, `tsc -p tsconfig.web.json` and `eslint src tests` all exit 0.

**Review.** One adversarial read-only review (eight areas, every finding independently checked by a second reader) confirmed eight defects, all fixed in `5c3e2d4` before this build: a persisted outcome token that would have vanished after a restart, a profile-import allow-list that refused every companion choice (the most serious), Laser Mode overriding an explicit Sleep command, a prototype-name lookup in the journal text, ambiguous import-preview labels and three stale or wrong test expectations. Four of the eight review areas found nothing. A review is not a test.

## What is NOT verified

- **No runtime evidence at all for 1.5.0.** The Living Companion code (events, props, personalities, mood, Laser Mode, journal, the new pages and panel, the Android stage window) has never executed. Behaviour, drawing quality, animation feel, timing and battery use are UNVERIFIED.
- **The unit tests written for this release were never run.** Several of their expectations are hand-estimated (statistical bands, timing assumptions, pose margins) and may need adjusting when the owner's CI first runs the suite. The existing suites may also have expectations that no longer hold; the review looked for these by reading, not by running.
- **Installers were never run, installed or upgraded.** The silent-install, upgrade-from-1.3.0 and uninstall behaviour of the 1.5.0 installers is not observed (the owner's real install is in use and the project rules forbid it).
- **Multi-monitor and mixed-DPI behaviour of props and the laser dot, the Windows laser dot over a real desktop, the Android 12+ pass-through of the wider non-touchable stage window at 0.8 opacity, and phone or tablet behaviour of the new panel** are all NOT RUN. The 1.4.2 owner verification covers one phone and none of this.
- **Tablets, other Android phones, Windows 10 and Windows on Arm hardware** have not been individually tested (the ARM64 installer was built on an x64 PC).
- **No claim** is made of SmartScreen trust, a verified publisher, Google Play approval, or that the app is free of malware (a static review does not prove that).

## If you rebuild

Any change to the sources invalidates the hashes: rebuild from a clean committed tree, run `npm run release:sums`, and refresh the table in [the release-notes draft](1.5.0-release-candidate.md) and this record.
