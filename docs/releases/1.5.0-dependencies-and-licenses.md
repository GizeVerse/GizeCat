# GizeCat 1.5.0 dependencies and licences

What GizeCat 1.5.0 depends on, what changed since 1.4.2, and the licences as the repository records them. Every row comes from `package.json`, `package-lock.json`, `THIRD_PARTY_NOTICES.md` and `android/app/build.gradle.kts` on the branch `feature/living-companion`.

- **No network audit was run.** `npm audit`, an advisory-database lookup, a licence scanner and a Gradle dependency resolution were not run (the working rules for this release candidate forbid network access and builds during documentation). Absence of a finding here means nothing: nobody looked.
- Licences are quoted from `THIRD_PARTY_NOTICES.md`. Where that file records nothing, this page says so and does not guess.
- Nothing here is legal advice, and nothing in 1.5.0 has been run (status: IMPLEMENTED, statically verified only).

## 1. What changed since 1.4.2

Compared with `git diff 25b22b8..HEAD -- package.json package-lock.json android/` (the 1.4.2 baseline commit to the 1.5.0 candidate):

| File | Change |
|---|---|
| `package.json` | `version` 1.4.0 to 1.5.0. **No dependency line changed** |
| `package-lock.json` | The two `version` fields (root and `packages[""]`) 1.4.0 to 1.5.0. No package, version, resolved URL or integrity entry changed |
| `android/version.properties` | `versionName` 1.4.2 to 1.5.0, `versionCode` 10403 to 10500, plus an updated comment |
| `android/app/src/main/java/io/github/gizeverse/gizecat/OverlayWindow.kt` | Source change, not a dependency: the visual overlay window may grow into a wide, short "stage" strip for world-event props and the laser dot (new limits `MAX_STAGE_W_DP` 4096 and `MAX_STAGE_H_DP` 900; the touch window keeps its own 600 dp bound) |
| `android/app/build.gradle.kts`, other Gradle files, `AndroidManifest.xml` | **Unchanged** |
| `THIRD_PARTY_NOTICES.md`, `electron-builder.yml` | **Unchanged** |

So the premise "only the version changed" is true for `package.json`, `package-lock.json` and the Gradle build, and not quite true for `android/`: one Kotlin source file also changed, and it adds no library. **The Living Companion work added no dependency**: no npm package, no Gradle library, no font, sound or image file from a third party. The new props, laser dot and clips are drawn by the project's own renderer code (`src/renderer/overlay/props.ts` and the rig), and `package.json` and the Gradle build list nothing that could supply sounds or art; `THIRD_PARTY_NOTICES.md` still states that no third-party art, sprites, fonts or sounds are included.

## 2. npm (desktop and web)

`package.json` declares one runtime dependency and the rest as development dependencies. Versions are exact pins.

| Package | Version | Reaches users as | Licence (per `THIRD_PARTY_NOTICES.md`) |
|---|---|---|---|
| `koffi` | 3.3.4 | Native FFI module in the Windows installers (unpacked from `app.asar`); not shipped on macOS, in the web build or in Android | MIT, (C) Niels Martignene |
| `@koromix/koffi-win32-x64` / `@koromix/koffi-win32-arm64` | 3.3.4 | The prebuilt koffi binary of each installer's own architecture (not in `package.json`; the ARM64 one is staged into `node_modules` by `scripts/stage-koffi-arch.mjs` from the version and hash in the lockfile) | MIT, same author; the packages carry no licence file of their own, only a `package.json` declaration |
| node-addon-api, node-api-headers | as bundled by koffi 3.3.4 | Vendored inside koffi | MIT |
| Electron | 44.9.3 | The runtime in every installer (declared in `devDependencies` and in `electronVersion` of `electron-builder.yml`, because electron-builder packs it) | MIT, with Chromium (BSD-3-Clause and others) and Node.js (MIT and others) notices shipped in the install folder |
| `zod` | 4.6.7 | Bundled into the application JavaScript (desktop, web and the Android web bundle) by esbuild; declared in `devDependencies` because it is compiled in, not installed | MIT, (C) Colin McDonnell |

The UI Automation helper `DesktopCatUia.exe` is the project's own code, compiled with the .NET Framework's C# compiler; no .NET assemblies are redistributed.

### 2.2 Build-time and test-time only (not shipped)

All in `devDependencies`: `@electron/fuses` 2.1.3, `@eslint/js` 10.0.1, `@playwright/test` 1.64.1, `@types/node` 24.19.2, `electron-builder` 26.18.1, `esbuild` 0.28.2, `eslint` 10.13.0, `typescript` 6.0.3, `typescript-eslint` 8.72.1, `vitest` 5.0.5 (plus `electron` and `zod` above, which are packed or bundled rather than installed).

Licences as recorded in `THIRD_PARTY_NOTICES.md`: MIT for electron-builder, esbuild, Vitest, ESLint, typescript-eslint and @electron/fuses; Apache-2.0 for TypeScript and Playwright. `@eslint/js` and `@types/node` are not named in that file, so this page records **no licence for them**. NSIS (zlib/libpng licence) is downloaded by electron-builder; its stub is part of each installer. rcodesign 0.29.0 (MPL-2.0), used only for the ad-hoc macOS zips of 1.4.0, is not part of 1.5.0's Windows and Android scope.

Transitive npm packages (the thousands of entries under `node_modules` that electron-builder, ESLint and others pull in) are in `package-lock.json` but are not individually listed in `THIRD_PARTY_NOTICES.md`; none of them ships to users, apart from those of koffi named above. Their licences were not collected for this report.

## 3. Android (Gradle)

`android/app/build.gradle.kts` declares two direct dependencies, unchanged since 1.4.2:

| Dependency | Version | Licence (per `THIRD_PARTY_NOTICES.md`) |
|---|---|---|
| `androidx.webkit:webkit` | 1.14.0 | Apache-2.0, (C) The Android Open Source Project |
| `androidx.core:core` | 1.17.0 | Apache-2.0, (C) The Android Open Source Project |

`THIRD_PARTY_NOTICES.md` also lists the resolved transitive libraries that end up in the APK and AAB (androidx annotation, collection, lifecycle, startup, profileinstaller, tracing and others; Kotlin standard library 2.2.10; kotlinx-coroutines 1.8.1; JetBrains annotations 23.0.0; Guava listenablefuture 1.0; JSpecify 1.0.0), all recorded as Apache-2.0. That list was produced for 1.4.0 and its heading still says "1.4.0". No Gradle file changed afterwards, so the recorded list is expected to still hold, but it was **not re-resolved** for 1.5.0 (that needs Gradle, which was not run here).

Build tools, not shipped in the APK or AAB: Android Gradle Plugin 9.0.1 (with D8/R8 and lint), the Kotlin compiler 2.2.10 and Gradle 9.1.0, all recorded as Apache-2.0. The Gradle wrapper files are committed in the repository.

Other facts from the build file: `minSdk` 29, `targetSdk` and `compileSdk` 36, `dependenciesInfo.includeInApk = false` (no Google dependency-metadata block in the APK), R8 minification and resource shrinking on for release and trial. Android System WebView draws the page; it is part of the device and is not redistributed. The launcher icon is the project's own artwork.

## 4. The project's own licence and artwork

GizeCat is MIT-licensed (`LICENSE`, and `"license": "MIT"` in `package.json`). All cat artwork, animations, props and icons are original and drawn procedurally in code; no third-party fonts or sounds are included. The settings window uses system fonts installed with the operating system.

## 5. Known gaps to fix before publishing (owner or maintainer)

These are documentation gaps, not new dependencies, and they sit in a file outside this page's scope:

- `THIRD_PARTY_NOTICES.md` still labels the Android section "(`android/`, 1.4.0)" and the macOS line "(1.4.0)". The content matches the unchanged dependency set, but the version labels are stale. Updating them changes a file that the packaged installers include, so do it deliberately and rebuild.
- The Android library list was not re-resolved for 1.5.0 (section 3).
- No `npm audit`, no advisory check and no licence scan was run. Run them yourself, with network access, before publishing, and record the result with its date.

## 6. How to re-check this page

```text
git diff 25b22b8..HEAD -- package.json package-lock.json android/
```

This reads files only. A fresh licence and advisory check (`npm audit`, a Gradle dependency report) needs the network and the build tools; run it on a machine where that is allowed.
